## 3. 🔴 Критичные проблемы

### 3.1. «Живой мониторинг» в веб-интерфейсе не опрашивает свечи автоматически

**Файл:** `app.py:140–156`

**Проблема:** README обещает: *«бот опрашивает закрытие каждой 15-минутной свечи»*. В коде нет ни `streamlit-autorefresh`, ни цикла `sleep + st.rerun()`. Streamlit перезапускает скрипт **только при действиях пользователя**. Тумблер «▶️ Включить живой мониторинг» включён, но без кликов пользователя новые свечи не проверяются.

**Затронуто:** только веб-режим. Консольный демон `bot.py` имеет корректный планировщик (`bot.py:78–97`).

**План исправления:**
1. Установить пакет: `pip install streamlit-autorefresh`, добавить в `requirements.txt`.
2. В `app.py` при активном `is_monitoring` вызвать:
   ```python
   from streamlit_autorefresh import st_autorefresh
   if is_monitoring:
       st_autorefresh(interval=60_000, key="monitoring_refresh")
   ```
3. Альтернатива без зависимости: `time.sleep(60)` + `st.rerun()` в конце блока мониторинга (хуже — блокирует UI).

**Приоритет:** 🔴 Высший

---

### 3.2. `bot.py` анализирует одну свечу повторно (нет дедупликации)

**Файл:** `bot.py:38–76`

**Проблема:** Планировщик запускает анализ через 5 сек после закрытия свечи (`:00:05, :15:05, :30:05, :45:05`). Yahoo Finance часто **не успевает** отдать только что закрывшуюся свечу. Тогда `get_market_data()` возвращает предыдущую свечу, и бот тратит API-вызов на повторный анализ уже обработанных данных, создавая дубли в БД.

**Ключевая деталь:** поле `candles_hash` сохраняется в БД (`core.log_signal()`), но **нигде не используется** для проверки «уже анализировали». В `app.py` дедупликация есть (`st.session_state.last_auto_candle`), в `bot.py` — нет.

**План исправления:**
1. Добавить в `core.py` функцию:
   ```python
   def get_last_analyzed_candle_time():
       """Возвращает время последней проанализированной свечи из БД (из raw candles_hash нельзя — хранить time отдельно)."""
   ```
   Проще: добавить в таблицу `signals` колонку `last_candle_time TEXT` (миграция через `ALTER TABLE` по образцу `outcome` в `init_db()`).
2. В `bot.analyze_market()` после получения свечей: если `candles[-1]['time'] == last_candle_time из БД` → пропуск цикла с логом.
3. Альтернатива/дополнение: перенести запуск планировщика с `:05` секунд на `:30–:45` секунд после закрытия (данные Yahoo успеют обновиться).

**Приоритет:** 🔴 Высший

**Приоритет:** 🔴 Высший

## 4. 🟡 Средние проблемы

### 4.1. Prompt Caching «со скидкой 90%» работает только для Anthropic

**Файлы:** `core.py:23, 282–285`, `README.md:29–30`

**Проблема:** `cache_control: {"type": "ephemeral"}` — Anthropic-специфичный механизм. Дефолтная модель проекта — `z-ai/glm-5.2`, которая этот параметр проигнорирует (OpenRouter просто отбросит). README подаёт кэширование как универсальную фичу, но реальная экономия 90% достижима только на `anthropic/claude-3.5-sonnet`.

**План исправления:**
1. В README добавить оговорку: кэширование работает на моделях Anthropic.
2. Опционально: выводить в UI предупреждение «модель не поддерживает prompt caching», если выбранная модель не содержит `anthropic`/`claude`.

**Приоритет:** 🟡 Средний

---

### 4.2. Рассинхрон дефолтной модели

**Файлы:** `.env.example:2` (`anthropic/claude-3.5-sonnet`), `core.py:23` (`z-ai/glm-5.2`), `app.py:74–79`

**Проблема:** Три разных источника дефолта. Селекбокс модели в `app.py` **вообще не читает** env-переменную `MODEL` — пользователь, задавший модель в `.env`, всё равно увидит `glm-5.2` в UI.

**План исправления:**
1. Привести к единому дефолту `core.DEFAULT_MODEL` во всех местах.
2. В `app.py` задать `index=` для `st.selectbox` на основе `os.getenv("MODEL", core.DEFAULT_MODEL)`.

**Приоритет:** 🟡 Средний

---

### 4.3. `importlib.reload(core)` перечитывает книги на каждый rerun

**Файл:** `app.py:10–12`

**Проблема:** Каждый rerun Streamlit делает `reload(core)`, что сбрасывает `_book_cache` → файл `VSA_REFERENCE.md` (~118 КБ) перечитывается с диска при каждом взаимодействии с UI. Работает, но расточительно; коммит `78a1b2c` вводил это как фикс кэширования Streamlit — костыль.

**План исправления:** убрать `importlib.reload(core)`; если нужна горячая перезагрузка при разработке — обернуть в флаг окружения (`if os.getenv("DEV_RELOAD"): ...`). Кэш книг сохранится между rerun.

**Приоритет:** 🟡 Средний

## 7. Что менять НЕ нужно (сильные стороны)

- ✅ **Математика риск-менеджмента в Python, а не в LLM** — ключевое правильное решение; LLM даёт уровни, Python считает лоты и валидирует.
- ✅ **Локальный расчёт VSA-признаков** — LLM получает готовую математику, а не сырые данные: меньше токенов, меньше галлюцинаций.
- ✅ **Конспект книг вместо полных текстов** (~35k vs ~500k токенов) — осмысленная экономия.
- ✅ **Фолбэки в `extract_signal`** (markdown → голый JSON → None) — устойчивый парсинг.
- ✅ **Retry/backoff с обработкой 429 и `Retry-After`** в `call_llm`.
- ✅ **Честная read-only интеграция MT5** — README не обещает автоторговлю, которой нет.
- ✅ **Тесты на ключевую бизнес-логику** (`calculate_position_size`, stale-данные, парсинг сигнала).
